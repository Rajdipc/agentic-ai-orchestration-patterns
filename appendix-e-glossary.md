# Appendix E: Glossary of agentic AI terms

[← Previous: Appendix D — The Agentic AI Threat & Defense Catalog](./appendix-d-agentic-threat-and-defense-catalog.md) | [Book Index](./README.md) | [Test yourself: Chapter 18 (105 MCQs) →](./chapter-18-mcq-assessment-and-case-studies.md)

This appendix is the alphabetical reference for the patterns, protocols, metrics, and acronyms used across the handbook. Each entry gives a short definition that matches how the chapters use the term. The "See:" links after it point to the chapters or reference appendices where the idea is worked out in depth: [Appendix A](./appendix-a-rag-patterns-deep-dive.md) (RAG patterns), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md) (reasoning and planning patterns), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md) (agent benchmarks and evaluation datasets), and [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md) (threats and defenses).

A few conventions before you start:

* Pattern numbers (`1.x`–`4.x`) refer to the book's complexity levels, not to chapters. Level 1 lives in Chapter 2, Level 2 in Chapter 3, Level 3 in Chapter 4, and Level 4 in Chapter 5.
* Some entries are this handbook's own working vocabulary rather than industry-standard names, for example TBOM, CpO, the Three Engineering Laws, and the Four-Plane Agent Protocol Stack. Those are marked *(book term)*.
* Attributions (who created a protocol, which paper named a pattern) are kept short, and the [Primary sources](#primary-sources-for-key-terms) table at the end links the originals. Numbers quoted from papers, such as task counts and reported gains, are as stated in the cited source. I've left leaderboard scores out on purpose, because they go stale quickly.
* Version-sensitive terms follow the versions the book targets: MCP spec `2026-07-28` and A2A v1.0 (see [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md)). Protocol and framework details change often, so check the current spec before you rely on a field name.

To find a specific acronym, use your browser's find (Ctrl/Cmd + F) or jump by letter below. Terms that begin with a number or symbol are filed under their spelled-out word: *4-Tier Golden Dataset* is under G, and *τ-bench* is under T.

## A

* **A2A (Agent2Agent Protocol):** Open protocol for horizontal ("east–west") communication between independently owned agents across framework and organizational boundaries. A client agent discovers a remote agent through its **Agent Card** and delegates goals as stateful **Tasks**, without ever seeing the remote agent's prompts, memory, or tools (*opacity*). Created by Google (April 2025) and now a Linux Foundation project; the book targets v1.0. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **A2UI (Agent-to-User Interface):** Open-source, declarative UI protocol released by Google in late 2025. The agent sends UI as *data*: a flat list of components with ID references, drawn only from component catalogs the client has advertised, and bound to a separate data model through JSON Pointer paths. It is transport-agnostic (it can ride on A2A, AG-UI, or other channels) and implements Tier 2 of **Generative UI**. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **ABC (Agentic Benchmark Checklist):** Guidelines (Zhu et al., 2025) for building and auditing agent benchmarks. They split validity into **task validity** (a task is solvable *if and only if* the agent has the target capability) and **outcome validity** (the success signal really means the task was done). The authors report that flaws in either can misstate measured performance by up to 100% in relative terms; their examples include insufficient tests in SWE-bench Verified and τ-bench counting empty responses as successes. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Ablation Eval (With-vs-Without):** Running the same eval suite twice, once with a candidate component (typically a skill) and once without it, over repeated trials, and comparing pass rate, step count, and token cost before admitting the component. See: [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **ACE (Agentic Context Engineering):** A learned-procedural-memory method (Zhang et al., 2025) that keeps an evolving "playbook" which a reflector/curator updates with small incremental deltas after each task, instead of rewriting it wholesale. See: [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md).
* **ACI (Agent–Computer Interface):** The tools, commands, parameter schemas, and feedback formats an agent works through, designed as deliberately as a human UI. The term was popularized by the SWE-agent paper (Yang et al., NeurIPS 2024). Good ACI means task-oriented, namespaced tools with mistake-proof ("poka-yoke") arguments, compact outputs, and actionable errors. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **ACP (Agentic Commerce Protocol):** Checkout-layer commerce protocol from OpenAI and Stripe (September 2025). It defines a merchant checkout API for in-chat purchases, paid with scoped, time-limited payment tokens. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **Adaptive-RAG:** Complexity-based retrieval routing (Jeong et al., NAACL 2024). A lightweight classifier sends each query down one of three paths: no retrieval, single-step retrieval, or an iterative multi-step loop, so easy queries don't pay for the expensive path. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **AG-UI (Agent–User Interaction Protocol):** Open, event-based, transport-agnostic protocol (originated by the CopilotKit team) that streams typed events between an agent backend and a frontend: lifecycle events (`RUN_STARTED`, `STEP_STARTED`, …), text-message streaming, tool-call streaming (`TOOL_CALL_*`), and state synchronization (`STATE_SNAPSHOT`, `STATE_DELTA`). It is the northbound "pipe" of the four-plane stack. For human-in-the-loop UI, the client can declare its own **frontend-executed tools** (for example, an approval card): when the model calls one, the run ends, the frontend renders it, and a new run resumes with the user's decision as a tool message. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **AG2:** An independent community fork that continues the AutoGen 0.2 lineage under open governance. It is a different codebase from **Microsoft Agent Framework**, which is Microsoft's own successor to AutoGen and Semantic Kernel. See: [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Agent:** A system in which the LLM dynamically directs its own process and tool use, deciding the next action at runtime and when it is done. A compact working definition the industry converged on in 2025 (popularized by Simon Willison): *"an LLM agent runs tools in a loop to achieve a goal."* **Workflows** and agents together make up *agentic systems*. Contrast **Workflow**. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md).
* **Agent Card:** A2A's JSON capability document, conventionally served at `/.well-known/agent-card.json`. It declares the agent's identity, supported interfaces and transports, capabilities (such as streaming and push notifications), security schemes, and high-level skills. Cards can be JWS-signed, and authenticated clients can fetch an extended card. Treat its text as untrusted input. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Agent Quality Flywheel:** The closed loop that turns production telemetry into improvements: Observe → Curate & Mine → Diagnose → Optimize → Gate & Rollout, then back to Observe. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **Agent Session Smuggling:** Cross-agent injection technique described by Palo Alto Networks Unit 42 (October 2025): a malicious remote agent slips covert instructions into an established, stateful A2A session between otherwise normal turns. Unit 42 notes it exploits implicit trust between agents rather than a flaw in the A2A protocol itself. Mitigations include human approval for critical actions, verifying remote agents, and checking that instructions stay on-task. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Agent Skill:** A self-contained folder of procedural know-how: a required `SKILL.md` (YAML frontmatter plus a Markdown playbook) and optional `scripts/`, `references/`, and `assets/` directories, loaded through **progressive disclosure**. Anthropic introduced the format in October 2025 and published it as an open specification. See: [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md).
* **AgentBench:** Broad "LLM-as-agent" benchmark (Liu et al., ICLR 2024) with eight multi-turn environments: operating system, database, knowledge graph, digital card game, lateral-thinking puzzles, house-holding, web shopping, and web browsing. The combined overall score hides very different skills, so read the per-environment breakdown. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **AgentDojo:** Extensible environment (Debenedetti et al., NeurIPS 2024 Datasets & Benchmarks) that measures an agent's utility and its robustness to indirect prompt injection together: 97 realistic user tasks (email, e-banking, travel, workspace tools) and 629 security test cases, with pluggable attacks and defenses. It reports benign utility, utility under attack, and **attack success rate**. A low ASR against the built-in attacks does not prove robustness against adaptive attackers. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **AgentHarm:** Misuse benchmark (Andriushchenko et al., ICLR 2025) of explicitly malicious multi-step agent tasks across 11 harm categories, run with synthetic tools. It reports a **refusal rate** and a **harm score**, which is high only when the agent both fails to refuse *and* competently completes the task. It measures misuse, not prompt-injection robustness. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Agentic RAG:** RAG in which retrieval is a control loop rather than a fixed pipeline. The agent decides whether, what, and how often to retrieve; it rewrites and decomposes queries, grades evidence, queries several stores, and verifies citations before answering. At enterprise scale, **Multi-Agent Federated RAG** has an orchestrator fan out to modality-specialist retriever agents (vector, graph, semantic SQL) and a citation-verifying synthesizer. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Agentic Saga:** Transaction pattern for multi-step workflows that mutate external systems. After each forward step succeeds, register a compensating action; if a later step fails permanently, run the compensations in reverse (LIFO) order. A compensation is a *semantic* undo (a refund), not a rollback. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Agents-as-Tools:** A supervisor implementation in which each specialist sub-agent is wrapped as a callable tool (for example `agent.as_tool()` or `AgentTool`). The caller keeps control and receives only the result, so the sub-agent's tool noise never enters the caller's context. Contrast **Handoff**. See: [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **AI-BOM (AI / ML Bill of Materials):** A machine-readable inventory of an AI system's models, datasets, and software dependencies, extending the SBOM idea to AI components (OWASP CycloneDX supports ML-BOMs). Diffing it between releases is a supply-chain detection signal. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Ambient Credentials:** Credentials a workload can pick up simply from where it runs, without being granted them for the task: a cloud metadata endpoint, mounted secrets, or inherited environment keys. Code-execution sandboxes should have no ambient credentials and default-deny egress, so that injected or generated code cannot turn into account compromise. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Amdahl's Law of Agent Latency** *(book term)*: The third engineering law. Sequential chains sum their step latencies, while a parallel fan-out costs $L_{\text{dispatch}} + \max_i(L_i) + L_{\text{synth}}$, so the serial planning and synthesis steps cap the speedup and tail latency grows with fan-out. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md).
* **AndroidWorld:** Mobile-agent benchmark (Rawles et al., ICLR 2025) of 116 programmatic tasks across 20 real Android apps on an emulator. Tasks are parameterized and generated dynamically, with success checks based on device state, which makes it a model of contamination-resistant task design. Report results over several seeds. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **AP2 (Agent Payments Protocol):** Open, payment-method-agnostic protocol announced by Google with a coalition of partners (September 2025) and built as an extension of A2A and MCP. It carries user authorization as signed **Intent, Cart, and Payment Mandates**, implemented as **Verifiable Digital Credentials**. Occasionally mis-written as "A2P". See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **Attack Success Rate (ASR):** The share of security test cases in which the attacker's injected goal is actually carried out; the main metric of prompt-injection suites such as **AgentDojo** and **InjecAgent**. Always report it next to utility (benign and under attack), because a defense that drives ASR to zero by destroying utility is not a win. Not to be confused with *ASR* meaning automatic speech recognition in [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md). See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Augmented LLM:** The basic building block of every agent node: a foundation model connected to retrieval, tools, and memory. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md).
* **Automated Red-Teaming Tools:** Open-source frameworks that fire adversarial probes (injection, jailbreak, data leakage) at an LLM application and score the responses, for example NVIDIA's garak (an LLM vulnerability scanner), Microsoft's PyRIT (Python Risk Identification Tool), and promptfoo (testing and red-teaming in CI). Point them at the *whole agent* (tools, memory, UI), not just the model, and add successful attacks to the adversarial tier of the golden set. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).

## B

* **Barge-In (Full-Duplex Interruption):** A user interrupting a live voice agent mid-utterance. Handling it well takes four things: VAD-triggered cancellation of the in-flight response, flushing the client's audio buffer, truncating the model's context to what the user actually heard, and echo cancellation so the agent doesn't interrupt itself. See: [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md).
* **Benchmark Contamination (vs. Benchmark Overfitting):** *Contamination* means test items or their solutions were in a model's training data. *Benchmark overfitting* means the system has been tuned to the test set even though no data leaked, through prompts, scaffold choices, hyperparameters, or repeated submissions. Mitigations: post-cutoff tasks, private or held-out splits, parameterized tasks, and a held-out slice of your own golden set that you never tune on. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **Best-of-$N$:** Sample $N$ complete candidates in parallel and pick one with an external verifier, a reward model, or a majority vote. With an external verifier, it adds information that the model cannot produce by thinking longer. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **BFCL (Berkeley Function-Calling Leaderboard):** Function-calling benchmark (Patil et al., ICML 2025) from the Gorilla project. It covers simple, multiple, parallel, and parallel-multiple calls plus **irrelevance detection** (correctly *not* calling a tool), graded by Abstract Syntax Tree (AST) matching and execution; later versions add multi-turn, stateful, and agentic evaluation. Versions measure different things, so always cite the one you used. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **Bi-Temporal Knowledge Graph:** A memory graph whose edges carry two timelines: **valid time** (`t_valid` / `t_invalid`, when a fact was true in the world) and **transaction time** (`t_created` / `t_expired`, when the system recorded and retired it). A contradiction *invalidates* the old edge instead of deleting it, so both "what is true now?" and "what was true then?" stay answerable. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Blackboard Architecture:** Pattern 4.2. Specialist agents ("knowledge sources") never message each other; they read from and write typed patches to a shared, versioned board, and a controller fires each specialist whose trigger precondition has newly become true. Originates in classic AI (HEARSAY-II). Requires trigger deduplication, snapshot reads, and conflict-recording reducers. See: [Chapter 5](./chapter-05-decentralized-and-emergent-topologies.md).
* **BM25:** Classic sparse lexical ranking function that scores exact term matches, weighted by term rarity (IDF) and length-normalized term frequency. Strong on identifiers and error codes; blind to synonyms and paraphrase. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **BrowseComp:** Browsing-agent benchmark (Wei et al., OpenAI, 2025) of 1,266 questions whose short answers are hard to find but easy to verify, written "inverted" from a known fact. It measures persistence and creativity in web search, not typical user queries, and scores are highly sensitive to search budget, so compare systems at a fixed budget. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md).

## C

* **CAG (Cache-Augmented Generation):** For a small, static knowledge base shared by every user, precompute and reuse the KV cache (or a provider-side context cache) of the whole corpus and skip retrieval entirely. It is bounded by the context window, goes stale on updates, and can't enforce per-user ACLs inside one shared cache. See: [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **CaMeL (CApabilities for MachinE Learning):** Prompt-injection defense (Debenedetti et al., 2025) that hardens the **Dual-LLM pattern**. A privileged LLM writes a program over symbolic variables; a custom interpreter executes it, attaches *capabilities* (provenance plus allowed readers) to every value, and checks security policies before each tool call, so untrusted data cannot change control flow or choose where data goes. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Canonical Context Window Layout:** Ordering every call's context from static to dynamic: a cacheable **static prefix** (system rules, tool schemas, skill catalog) → **session context** (retrieved memory, compacted summary, recent verbatim turns) → an **active suffix** (scratchpad, immediate instruction). It maximizes prefix-cache hits and exploits primacy and recency. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Chain-of-Thought (CoT) Prompting (Few-Shot / Zero-Shot):** Prompting a model to write intermediate reasoning steps before its answer. *Few-shot CoT* (Wei et al., NeurIPS 2022) puts worked `question → reasoning → answer` exemplars in the prompt; *zero-shot CoT* (Kojima et al., NeurIPS 2022) appends *"Let's think step by step."* Reasoning models make hand-written CoT largely redundant, and the visible chain is not a faithful record of what drove the answer (see **CoT Faithfulness**). See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md), [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Chain-of-Verification (CoVe):** Hallucination-reduction pattern (Dhuliawala et al., Meta; Findings of ACL 2024) in four steps: draft an answer, plan fact-checking questions about it, answer each question independently so the answers aren't biased by the draft, then write a verified final response. It is strongest when the verification step uses retrieval. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Checkpointer (Durable Checkpointing):** Persisting agent or graph state at step boundaries, keyed by a thread ID, so a run can pause for a human, survive a crash, and resume on any worker. For long business processes, teams often go further and run the loop inside a general **durable-execution engine**, which records every step's result. See: [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md), [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md).
* **CoALA (Cognitive Architectures for Language Agents):** Framework (Sumers, Yao, Narasimhan & Griffiths; arXiv 2023, TMLR 2024) whose four-way memory taxonomy (working, episodic, semantic, procedural) the book adopts as its shared vocabulary. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Code Gate (Deterministic):** Plain-code validation between workflow stages (schema checks, sanitization, business invariants) that retries, aborts, or escalates instead of letting bad output propagate. It raises effective per-stage reliability, but only for the error classes it can detect: valid-but-wrong output still passes a schema gate. See: [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md), [Chapter 1](./chapter-01-foundations-and-mental-models.md).
* **CodeAct:** Pattern (Wang et al., ICML 2024) in which the agent acts by writing executable code (for example, a Python script that calls tool functions, loops, and aggregates) instead of emitting one JSON tool call at a time, with execution inside an isolated sandbox. It collapses many tool turns into one and keeps intermediate data out of the context window. Production variants include programmatic tool calling and "code mode" over MCP tools. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md).
* **Compaction (Watermark Summarization):** When context crosses a token watermark, summarize the oldest turns into a structured summary while keeping recent turns verbatim, and never split a tool call from its result. Compaction is lossy and invalidates the prompt cache, so trigger it at a watermark rather than every turn. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Compound Reliability Decay ($R = r^N$)** *(book term)*: The first engineering law. If each of $N$ sequential steps independently avoids an *uncaught*, fatal error with probability $r$, end-to-end success is $r^N$ (for example, $0.95^{10} \approx 59.9\%$). It is the reason for code gates and verifiers between stages. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md).
* **Computer-Use Agent (CUA):** An agent that operates graphical interfaces the way a human does. Each step captures the screen (optionally with the DOM or accessibility tree), grounds the target (DOM references, pixel coordinates, or **Set-of-Mark**), emits a mouse or keyboard action in a sandboxed browser or VM, and verifies the post-action screen. See: [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Confused Deputy:** A privileged component, such as an agent or a shared MCP server running under a broad service account, that is tricked into using its authority for a caller who lacks it. Defeated with per-user, audience-bound delegated tokens plus row-level security. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Constrained Decoding (Strict Mode / Structured Outputs):** Generating tool arguments or a final response under a grammar compiled from a JSON Schema, so the output is guaranteed to parse and to follow the schema's structure. It guarantees *shape*, not correctness: some strict modes ignore or reject keywords such as numeric bounds, so runtime validation and business-rule checks are still required. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md), [Chapter 2](./chapter-02-single-agent-loops.md).
* **Context Engineering:** Curating the *entire* set of tokens the model sees on each call (instructions, tool definitions, retrieved knowledge, memory, history, and tool results), treating context as a finite resource. LangChain's taxonomy groups the techniques into four moves: *Write*, *Select*, *Compress*, and *Isolate*. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Context Rot:** Accuracy that degrades, non-uniformly, as input length grows, especially with distractors (documented in Chroma's July 2025 report). Related long-context failures are **poisoning** (a hallucinated or outdated fact reused as true), **distraction** (history pulling the model toward repeating past actions), and **clash** (contradictory information derailing the answer). See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **CoT Faithfulness (Unfaithful Reasoning):** Whether a model's visible reasoning reflects what actually drove its answer. Turpin et al. (NeurIPS 2023) showed CoT explanations that omitted a bias the model had followed, and Chen et al. (Anthropic, 2025) found that reasoning models often did not mention hints they had used. Treat reasoning text as unreliable evidence: log tool calls, evidence IDs, and verifier results as the record of why the agent acted. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **CpO (Cost per Validated Outcome)** *(book term)*: The book's "true north" FinOps metric: total spend across *all* runs, failed ones included, divided by the number of runs that pass trajectory and outcome verification. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **CRAG (Corrective RAG):** Pattern (Yan et al., 2024) that inserts a retrieval evaluator between retrieval and generation. In the paper, a lightweight fine-tuned evaluator triggers *Correct* (refine the documents into "knowledge strips"), *Incorrect* (discard and fall back to web search), or *Ambiguous* (do both). CRAG checks the *input* to generation; **Self-RAG** checks the *output*. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **CRITIC (Tool-Interactive Critiquing):** Self-correction method (Gou et al., ICLR 2024) that iterates *verify → correct*: the model checks its draft with a task-appropriate tool (search for facts, a code interpreter for programs, a classifier for toxicity), writes a critique grounded in the tool output, and revises. Appendix B treats it as the default critique pattern, because the feedback carries information the generator did not have. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Cross-Agent Prompt Injection:** Prompt injection carried in a peer agent's messages, artifacts, or Agent Card text, which can spread through a multi-agent system (Lee & Tiwari's *Prompt Infection*, 2024, demonstrated self-replicating LLM-to-LLM injection). A signed Agent Card proves who published it, not that the agent's output is safe, so treat all peer output as untrusted and authorize per skill. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **Cross-Encoder Reranker:** A model that reads the query and a passage *together*, with full cross-attention, to re-score a retriever's top candidates (for example, ~50 down to 5–10). Too slow to score a whole corpus, so it serves as the precise second stage after a high-recall retriever. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).

## D

* **Deep Research:** Agentic RAG at the top end: a lead agent plans, parallel sub-agents search and read in their own context windows, a reflection step finds gaps, and a writer synthesizes a cited report. Very high quality on broad questions, at minutes of latency and many times the tokens of a chat. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Denial of Wallet (DoW):** An attack that runs up inference or tool costs on pay-per-use services instead of knocking the service offline; for agents it usually arrives through injected or emergent loops, recursive delegation, or huge fan-out. OWASP covers it under LLM10:2025 Unbounded Consumption. Countered with request-scoped budget circuit breakers (**TokenBudgetEnforcer**), turn caps, rate limits, and quotas. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Distillation (Trajectory Distillation):** Training a faster, cheaper Student model on a frontier Teacher's *verified* agent trajectories, filtered by rejection sampling and trained via SFT, DPO, and/or RFT, to down-tier cost and latency on narrow, high-volume tasks. Check the teacher's terms of service first. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **DPO (Direct Preference Optimization):** Preference fine-tuning on chosen/rejected pairs (Rafailov et al., 2023). For agents, a failed attempt and its verified self-healed correction form a pair, and both must be built on the *same* pre-error context. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Drift:** Gradual loss of production quality from input distribution shift, tool and environment changes, or model and prompt changes (including providers re-pointing floating model aliases). Countered by pinning dated model versions and gating every change on evals. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Dual-LLM Pattern:** Privilege separation proposed by Simon Willison (2023). A privileged LLM plans and calls tools but never sees untrusted text; a *quarantined* LLM reads untrusted text but has no tools; they communicate through symbolic variable references. **CaMeL** hardens this design. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Dynamic Tool Retrieval (Tool-RAG / Tool Search):** Indexing a large tool catalog and binding only the top-$K$ relevant schemas for the current step, via a meta-tool or a pre-turn filter, while keeping a small stable core set. Provider-native variants defer tool loading (for example, Anthropic's Tool Search Tool with `defer_loading`). Must be designed so it doesn't invalidate the prompt cache. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).

## E

* **Eager vs. Lazy Tool Loading:** *Eager* loading binds every MCP tool schema into each call, burning tokens and hurting tool selection. *Lazy* loading keeps a few high-frequency tools native and lists the rest by name behind meta-tools (inspect a schema, then call the tool). See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Egress Allowlist (Default-Deny Egress):** Routing all agent and sandbox network traffic through a proxy that blocks every destination not explicitly allowed, including cloud metadata endpoints. It closes the external-communication leg of the **lethal trifecta** at the network layer, so a missed classifier or sanitizer does not become a data leak. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Elicitation:** MCP feature that lets a server ask the human user for missing information or confirmation mid-request. **Form mode** collects structured input against a restricted JSON Schema and must never be used for secrets; **URL mode** sends the user to an external page so sensitive data never passes through the client or the LLM. It remains active in `2026-07-28`, delivered through **MRTR**. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **Episodic Memory:** Records of past experiences and trajectories (what was tried, what failed, what fixed it), usually stored as indexed episode summaries and recalled as lessons or dynamic few-shot examples. Reflexion's lesson buffer is episodic memory. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Error-as-Observation:** Catching tool exceptions and returning them to the model as *actionable* observations (what was wrong, what is valid) instead of crashing the loop, so the agent can self-heal. The runtime should retry transient errors itself, return model-correctable errors as hints, and tell the model to stop on fatal ones. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md).
* **Evaluator–Optimizer (Generator–Critic):** Pattern 3.2. A Generator and a *separate* Critic agent (fresh context, opposing persona, asymmetric tools, often a different model family) iterate until the Critic reports no blocking defects or a round cap is reached. Ground the Critic with deterministic checks, and separate blocking defects from minor suggestions. See: [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Excessive Agency (LLM06):** The OWASP LLM Top 10 (2025) risk that a system can take damaging actions because it has *excessive functionality* (tools it doesn't need), *excessive permissions* (tools running with broader rights than needed), or *excessive autonomy* (high-impact actions without approval). It is the central risk for agents; mitigate with minimal toolsets, scoped delegated tokens, and risk-tiered human approval. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Exfiltration Channel:** Any path by which attacker-influenced text can pick a destination or carry data out of the trust boundary: auto-fetched Markdown or HTML images, clicked or unfurled links, write-capable tools (email, HTTP, tickets), sandbox network egress, shared memory, and peer agents. Inventory every channel, then close them with output sanitization plus a Content Security Policy, default-deny egress, and taint rules that stop untrusted data from choosing a destination. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md), [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md).

## F

* **Four Multi-Agent Triggers** *(book term)*: The conditions that justify splitting one agent into several: tool overload, context-window pollution, conflicting personas or instructions, and parallelizable latency. Each has a cheaper single-agent fix to try first. See: [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md).
* **Four-Plane Agent Protocol Stack (4-Protocol Stack)** *(book term)*: The mental model that maps protocols to responsibilities: *northbound* UX (AG-UI + A2UI, plus MCP Apps), *east–west* peers (A2A), *southbound* tools and data (MCP), and *commerce & trust* (AP2). The planes overlap: AP2 rides on A2A/MCP, and MCP Apps ships UI from the tool plane. Chapter 9 introduces two of the planes as *vertical* (MCP) and *horizontal* (A2A) integration; Chapter 15 completes the stack. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).

## G

* **GAIA:** General-assistant benchmark (Mialon et al., ICLR 2024) of 466 questions that are conceptually simple for humans but need multi-step reasoning, web browsing, file handling, and tool use. Short answers are graded by normalized exact match and reported per difficulty level; answers to most questions are kept private for a hidden test leaderboard, which is preferable to the long-public validation split. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **Generative UI:** Agents answering with interactive components instead of walls of text, in three tiers: (1) *static / mapped* components chosen by tool name, (2) *declarative* schema-driven UI from a trusted catalog (A2UI), and (3) *open-ended sandboxed* HTML/JS in an isolated iframe (for example, MCP Apps). See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **Generator–Verifier Gap (Coverage vs. Selection):** The gap between **coverage** (the share of problems where at least one of $k$ samples is correct, i.e. `pass@k`) and **selection accuracy** (how often a vote, verifier, or judge actually picks a correct sample). *Large Language Monkeys* (Brown et al., 2024) showed coverage climbing with sample count while majority voting and reward models plateaued in domains without automatic verifiers. Extra samples pay off only when something can select among them. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **GEPA:** Reflective prompt-evolution optimizer (Agrawal et al., 2025; available as `dspy.GEPA`). It reflects on full trajectories in natural language, proposes prompt edits, and keeps a **Pareto frontier** of candidate prompts rather than a single best one. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Golden Dataset (4-Tier Stratified):** An eval set stratified into (1) core happy path, (2) complex multi-hop and compound intents, (3) adversarial, edge-case, and error-recovery cases, and (4) multi-turn stateful and handoff conversations (starting heuristic: ~30/30/25/15%). Report scores per tier, not just in aggregate. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Golden Rule of Agentic Architecture** *(book term)*: Always use the most deterministic and simplest architecture that solves the problem; hand control flow to an LLM only at the nodes where the execution path cannot be known at design time. The typical result is a **Deterministic–Agentic Hybrid**: a deterministic outer state machine with bounded agentic loops inside specific nodes. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Graph of Thoughts (GoT):** Generalization of Tree-of-Thoughts (Besta et al., AAAI 2024) in which thoughts are vertices and dependencies are edges, so a controller can *generate* (branch), *aggregate* (merge several thoughts), and *refine* (loop on one thought). It executes a designed graph of operations rather than discovering one, so it suits divide → solve → merge problems whose decomposition is known in advance. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **GraphRAG:** Retrieval over graph-structured knowledge. In Microsoft GraphRAG (Edge et al., 2024), an LLM extracts an entity graph, Leiden clustering forms hierarchical communities, and pre-computed community summaries answer global "sensemaking" questions via map-reduce. Curated property graphs answer multi-hop topology questions by traversal. Cheaper variants (LazyGraphRAG, LightRAG, HippoRAG) are covered in Appendix A. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Grounded Reflexion** *(book term)*: Pattern 1.3. The book's variant of **Reflexion** that runs trustworthy external verifiers (tests, compilers, schema validators) *before* any rubric-based LLM critique, stores each failure as a lesson in an episodic buffer across trials, and escalates rather than shipping an unverified draft. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Groundedness (Faithfulness):** The degree to which every claim in an answer is supported by the retrieved context or tool observations. Measured with claim extraction plus NLI or LLM entailment, backed by deterministic citation checks. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **GRPO (Group Relative Policy Optimization):** RL algorithm introduced in DeepSeekMath (Shao et al., 2024) and used to train DeepSeek-R1. It scores a group of outputs sampled for the same prompt against each other instead of training a separate critic (value) model, and is typically paired with verifiable rewards such as correct answers or passing tests. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md), [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Guardrail Classifier:** A model or rule set that screens inputs, tool calls, or outputs for injection, jailbreaks, harmful content, or data leakage: open-weight safety and injection classifiers, open-source guardrail frameworks, or managed cloud services. It is a *probabilistic* layer: run it in blocking mode before side-effecting tools, and never make it the only control against indirect injection. It usually feeds a **Tripwire Guardrail**. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **gVisor:** Open-source, user-space application kernel written in Go that intercepts a container's syscalls. The book's strong default for cloud-native code sandboxes, between plain containers (shared kernel) and MicroVMs. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).

## H

* **HAL (Holistic Agent Leaderboard):** Cost-aware agent leaderboard and standardized evaluation harness led by Princeton researchers (Kapoor et al., 2025) that reports accuracy against cost across models, scaffolds, and benchmarks. Its large rollout study found that higher reasoning effort *reduced* accuracy in most runs, and LLM-aided log inspection caught agents searching for the benchmark instead of solving the task, a reminder to read logs, not just scores. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Handoff (Peer-to-Peer):** Transferring *active control* of a conversation from one specialist agent to another, which then talks to the user directly (typically via `transfer_to_<agent>` tools). A handoff-context policy decides what the receiver sees: full history, filtered history (for example, an SDK `input_filter` that strips tool calls), or only a summary note. Contrast **Agents-as-Tools**. See: [Chapter 5](./chapter-05-decentralized-and-emergent-topologies.md), [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Harness / Scaffold (Benchmark):** The **harness** runs an evaluation: it resets the environment, enforces step, time, and token budgets, handles retries and logging, and hands the end state to the grader. The **scaffold** is the agent's own loop, tools, and interfaces. Scaffold, budget, observation format, and harness or judge version can move a score as much as the model can, so freeze everything except the variable under test and report every version. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md).
* **Hermetic Sandbox (Stateful Mock Environment):** An eval environment that seeds in-memory state for each test case, binds the agent's tools to it, and asserts on both the trajectory and the *final mutated state*, with no production side effects. Record-and-replay of real responses complements it for known paths. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Hierarchical Supervisor:** Pattern 3.3. A central supervisor agent repeatedly picks which specialist to invoke, reads its structured report, and decides the next step or finishes. It scales into multi-level trees for large tool sets, at the cost of an extra LLM hop per level. See: [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md).
* **HITL (Human-in-the-Loop):** Putting human judgment into an agent run through three primitives (approve/reject gates, edit-state-and-resume, and time-travel), implemented with durable checkpoints and interrupts rather than blocked threads. Gate on risk, not on every call, to avoid approval fatigue. See: [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md), [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Hot-Path vs. Background Memory:** *Hot-path* memory work happens on the user's critical path: retrieval before a turn, and optional explicit writes during it. *Background* consolidation (fact extraction, contradiction resolution, memory updates) runs in queue workers after the turn and is eventually consistent. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **HuggingGPT-Style Task Planning (LLM as Controller):** Four-stage pattern (Shen et al., NeurIPS 2023): a controller LLM plans sub-tasks with dependencies, selects an expert model for each from its *description*, runs them, and summarizes the results. Its modern descendants are description-based routing over tool catalogs, skills, and Agent Cards, so selection quality is bounded by description quality. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **HumanEval / MBPP:** Function-level code-generation baselines, not agentic benchmarks (no environment, repository, or tools). HumanEval (Chen et al., 2021) has 164 hand-written Python problems with unit tests; MBPP (Austin et al., 2021) has 974 short entry-level Python tasks. Both are scored with `pass@k`, and both are now widely regarded as saturated and contamination-prone. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Hybrid Retrieval:** Combining lexical (BM25 / sparse) and semantic (dense vector) search, usually fused with **RRF** and followed by a **cross-encoder reranker**. This is the production baseline that fancier RAG patterns must beat. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **HyDE (Hypothetical Document Embeddings):** Query-side pattern (Gao et al., ACL 2023) in which an LLM drafts a hypothetical answer document and that document's embedding becomes the search key. The fake document may contain invented specifics, so it is used only for search, never as evidence. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).

## I

* **Idempotency Key:** A deterministic key the runtime computes for every mutating tool call (for example, from thread ID, step index, tool name, and canonical arguments) so that retries, checkpoint replays, and double-clicked approvals never execute the same mutation twice. The downstream system must honor the key, or you keep your own key-to-result ledger. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Improper Output Handling (LLM05):** OWASP LLM05:2025: passing model output to a shell, `eval`, SQL, an HTML or Markdown renderer, or another agent without validation or encoding, which can lead to XSS, SSRF, privilege escalation, or remote code execution. Treat model output as untrusted user input: parameterized queries, argument-vector process execution instead of shell strings, context-aware encoding, strict schemas, and sandboxed execution. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **InjecAgent:** Static benchmark (Zhan et al., Findings of ACL 2024) of 1,054 indirect-prompt-injection test cases spanning 17 user tools and 62 attacker tools. Each case embeds an attacker instruction in a simulated tool response and checks whether the agent then performs direct harm or data exfiltration. The metric is **attack success rate**; it is cheap and reproducible but measures no utility. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Instruction Hierarchy:** Model-side defense (Wallace et al., OpenAI, 2024) that trains an LLM to prioritize higher-privileged instructions (system, then user) over lower-privileged text such as tool outputs, so conflicting embedded instructions are ignored. It lowers injection success rates but gives no guarantee, so pair it with architectural controls. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Intent Routing (Multi-Intent Router):** Pattern 2.3. A fast classifier dispatches each request to the right specialist or sub-workflow. Use a multi-label `list[Intent]` schema so compound questions aren't cut in half, and don't treat a model's self-reported confidence as a calibrated probability. See: [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md).
* **Interleaved Thinking:** A reasoning model thinking *between* tool calls within a turn. The provider's opaque reasoning state (thinking blocks, thought signatures, or reasoning items, depending on vendor) must be sent back unchanged with the tool results, or multi-step tool use breaks or degrades. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Intrinsic Self-Correction:** A model revising its own answer with no external feedback (same model, same context, "review your answer and fix any mistakes"). Huang et al. (ICLR 2024) found that LLMs struggle to self-correct reasoning this way and sometimes get worse, which is why critics should be grounded in tests, compilers, validators, tools, or retrieval (**CRITIC**, **Grounded Reflexion**). See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md), [Chapter 2](./chapter-02-single-agent-loops.md), [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md).

## J

* **Jailbreak:** A user-supplied prompt crafted to get around a model's safety training or an application's policy (a form of direct prompt injection). In an agent, enforce authorization in code and give tools only the user's own rights, so that a successful jailbreak cannot reach beyond what the user could already do; jailbreak classifiers are detection signals, not guarantees. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **JSON Patch (RFC 6902):** Standard format that expresses changes to a JSON document as a list of operations (`add`, `replace`, `remove`, and others). AG-UI's `STATE_DELTA` events use it to keep frontend and agent state in sync without resending whole objects. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **JSON-RPC 2.0:** Lightweight remote-procedure-call message format. MCP uses it for all its messages, and A2A offers it as one of three protocol bindings (with gRPC and HTTP+JSON). See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).

## K

* **KV Cache:** The attention key/value tensors computed while a model processes (prefills) a prompt. Reusing them across requests that share an identical prefix (provider prompt caching, or self-hosted prefix caching in engines such as vLLM and SGLang) cuts time-to-first-token and, on hosted APIs, cost. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).

## L

* **LATS (Language Agent Tree Search):** Method (Zhou et al., ICML 2024) that adapts Monte Carlo Tree Search to language agents, searching over *actions in an environment* rather than just thoughts: select, expand, evaluate with an LM value function plus environment feedback, simulate, backpropagate, and reflect on failures. Affordable only in cheap, resettable environments, and unsafe where actions have irreversible side effects. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Least Agency:** Principle from the OWASP Top 10 for Agentic Applications that extends least privilege: don't give an agent more autonomy than the task needs, because unneeded agentic behavior widens the attack surface without adding value. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Least-to-Most Prompting:** Two-stage prompting (Zhou et al., ICLR 2023): decompose a problem into an ordered list of simpler sub-problems, then solve them in sequence, feeding each answer into the next. It targets easy-to-hard generalization and is the prompt-level ancestor of **Query Decomposition** and **Plan-and-Execute**. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Lethal Trifecta:** Simon Willison's (June 2025) warning that an agent combining (1) access to private data, (2) exposure to untrusted content, and (3) the ability to communicate externally is exposed to data exfiltration. Break at least one leg; even rendering an external Markdown image can be the third leg. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **LLM-as-a-Judge:** Using an LLM to grade open-ended outputs against a rubric. The book's five rules: deterministic checks first, decomposed binary (or 3-point) rubrics instead of 1–10 scales, reference-guided grading, mitigation of position, verbosity, and self-preference bias, and calibration against human labels. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **LLMCompiler:** Parallel function-calling framework (Kim et al., ICML 2024) that extends **ReWOO**'s up-front plan into a DAG: a planner emits tool tasks with explicit dependencies, a task-fetching unit dispatches each one when its inputs resolve, and an executor runs ready tasks concurrently before a join step answers or replans. Latency tracks the DAG's critical path, not the number of tasks. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md), [Chapter 2](./chapter-02-single-agent-loops.md).
* **Lost in the Middle:** The finding (Liu et al., TACL 2024) that models use information at the beginning and end of a long context far better than information in the middle, producing a U-shaped accuracy curve. Mitigated by context ordering and smaller, cleaner contexts. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).

## M

* **Magentic Orchestration:** Ledger-based orchestrator from Microsoft Research's Magentic-One system (2024). An outer loop maintains a **Task Ledger** (facts, guesses, plan) and an inner **Progress Ledger** checks progress, picks the next agent, and triggers replanning on stalls. Offered as a prebuilt orchestration in Microsoft Agent Framework. See: [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md), [Chapter 5](./chapter-05-decentralized-and-emergent-topologies.md).
* **Mandate (Intent / Cart / Payment):** AP2's signed authorization objects. An **Intent Mandate** captures the user's goal and constraints up front (the key primitive for human-not-present purchases); a merchant-signed **Cart Mandate** fixes the exact cart; a **Payment Mandate** tells the payment network and issuer that an agent is involved and whether the human is present. Mandates prove *authorization*, not good judgment. AP2 v0.1 focused on human-present card payments, with human-not-present flows on its published roadmap, so check the current spec status. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **"Mask, Don't Remove":** Context-engineering lesson from the Manus team: keep the tool list stable (preserving the prefix cache) and restrict which tools are callable through tool-choice constraints or logit masking, instead of adding or removing tool definitions mid-session. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **MAST:** A taxonomy of multi-agent failures (*"Why Do Multi-Agent LLM Systems Fail?"*, Cemri et al., 2025) that groups them into system-design/specification issues, inter-agent misalignment, and task verification and termination failures. See: [Chapter 5](./chapter-05-decentralized-and-emergent-topologies.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **MCP (Model Context Protocol):** Open protocol for vertical ("southbound") integration between AI applications and tools or data. Servers expose Tools, Resources, and Prompts over JSON-RPC 2.0, via `stdio` or **Streamable HTTP**, turning $N \times M$ custom connectors into $N + M$. Created by Anthropic (November 2024) and donated to the Linux Foundation's Agentic AI Foundation (December 2025); the book targets spec `2026-07-28`. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **MCP Apps:** Official MCP extension (SEP-1865) that lets a server ship interactive UI: tools link to `ui://` HTML resources, which the host renders in a sandboxed iframe connected by a JSON-RPC-over-`postMessage` bridge. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **MCP Host / Client / Server:** MCP's three participants. The **host** is the AI application that coordinates the LLM, permissions, and consent; a **client** is a connector inside the host holding a 1-to-1 connection with one server; a **server** exposes capabilities from a data source or API. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **MCP Primitives (Tools, Resources, Prompts):** **Tools** are model-controlled executable functions with an input schema and optional output schema; **Resources** are application-controlled, read-only data addressed by URI; **Prompts** are user-controlled, reusable templates (often surfaced as slash commands). See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **MCP Tasks:** Mechanism for long-running tool calls: the request returns a durable task handle that the client polls (`tasks/get`) instead of holding a connection open. Experimental in `2025-11-25`; in `2026-07-28` it is the official `io.modelcontextprotocol/tasks` extension (advertised through the new `extensions` capability), with `tasks/update` for sending follow-up input. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **Mem0:** Memory layer (Chhikara et al., 2025) in which an LLM compares each newly extracted fact with similar stored memories and chooses `ADD`, `UPDATE`, `DELETE`, or `NOOP`. It keeps the store compact but overwrites history. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **MemGPT / Letta:** OS-inspired virtual memory for agents (MemGPT; Packer et al., 2023), continued as the Letta framework. Small, editable **core memory** blocks stay pinned in context ("RAM"), while searchable **recall** and **archival** memory act as "disk"; the agent pages facts between them with memory tools. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Memory Poisoning:** Injected or false content written into an agent's long-term memory that re-triggers in later sessions, turning a one-time injection into a persistent, cross-session one (OWASP Agentic T1; ASI06 Memory & Context Poisoning). Defend with provenance tags on every memory write, no automatic promotion of untrusted tool output into memory, per-user or per-tenant namespaces, and memory the user can inspect and delete. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **METR Time Horizon (50% Task-Completion Time Horizon):** Metric (Kwa et al., METR, 2025): the length of tasks, measured in human-expert time, that an agent completes with 50% success, from a logistic fit of success against task length. The paper reported this horizon doubling roughly every seven months since 2019. A 50% threshold is far below production reliability, so translate it into `pass^k` terms before drawing deployment conclusions. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Microsoft Agent Framework:** Microsoft's unified successor to AutoGen and Semantic Kernel (Python and .NET). It provides graph-based Workflows with checkpointing and human-in-the-loop steps, prebuilt Sequential, Concurrent, Handoff, GroupChat, and Magentic orchestrations, and native MCP and A2A support. Contrast **AG2**, the community fork of AutoGen 0.2. See: [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **MicroVM (Firecracker):** A lightweight virtual machine with a dedicated guest kernel per sandbox (hardware virtualization via KVM). The book's strongest option for multi-tenant untrusted code execution and computer-use sandboxes. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **MIPROv2:** DSPy optimizer that jointly searches over instructions and few-shot demonstrations to maximize a metric on a validation set; a step beyond simple few-shot bootstrapping. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **MITRE ATLAS (Adversarial Threat Landscape for Artificial-Intelligence Systems):** MITRE's public knowledge base of adversary tactics, techniques, mitigations, and case studies against AI systems, modeled on MITRE ATT&CK. Where OWASP lists *risks*, ATLAS describes *adversary behavior*; use its technique IDs (for example, `AML.T0051` LLM Prompt Injection) in red-team plans, detection rules, and incident reports. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **MLE-bench:** Machine-learning-engineering benchmark (Chan et al., OpenAI, ICLR 2025) built from 75 Kaggle competitions: in a sandbox, the agent prepares data, trains models, and submits predictions that are graded against the historical human leaderboard, usually reported as the share of competitions earning a medal. Results scale with compute and wall-clock budget. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **MMR (Maximal Marginal Relevance):** Diversity reranking (Carbonell & Goldstein, 1998) that greedily picks the next document maximizing relevance to the query minus redundancy with documents already chosen, so the top-$k$ isn't five near-duplicates. See: [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Model Tiering:** Using frontier models only at high-leverage nodes (planner, replanner, judge) and small, fast models for high-volume executor and routing steps. Often the single largest cost lever. Distillation can later *down-tier* a node permanently by training a small Student on the frontier model's verified trajectories. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **MRR (Mean Reciprocal Rank):** Retrieval metric that averages $1/\text{rank}$ of the first relevant result across queries. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **MRTR (Multi Round-Trip Request):** The `2026-07-28` MCP pattern that replaces server-to-client requests. The server returns an `InputRequiredResult` listing its `inputRequests` (for example, an elicitation), and the client retries the original request with `inputResponses`. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **Multi-Agent Debate:** Pattern 4.3. Several agents propose answers independently (blind round 1), cross-examine each other with evidence over rounds with an early-consensus exit, and a judge renders the verdict (lineage: Du et al., 2023; Liang et al., 2023). Always benchmark it against a simple parallel sample-and-vote baseline first. See: [Chapter 5](./chapter-05-decentralized-and-emergent-topologies.md).

## N

* **Naive RAG:** A single-pass pipeline that embeds the raw query, retrieves a dense top-$K$ once, and generates. It fails on exact identifiers, vocabulary mismatch, multi-hop questions, and irrelevant retrievals. Appendix A's RAG Maturity Ladder calls it level L0. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Native Multimodal Streaming:** A single multimodal model that ingests audio (and, on some APIs, sampled video frames) and emits audio and tool calls over a persistent, bidirectional session, preserving tone and enabling natural turn-taking. Contrast the **cascaded** STT → LLM → TTS pipeline, which remains a valid choice when control, auditability, and model choice matter most. See: [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md).
* **Non-Blocking Async Tool:** In live voice or video sessions, running a slow tool in the background while the model keeps talking, then injecting the result into the still-open session, either natively or as a provisional result followed by a later update. See: [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md).

## O

* **OAuth 2.1:** An IETF draft that consolidates OAuth 2.0 best practices (such as mandatory PKCE and no implicit grant). MCP's authorization spec builds on it: remote MCP servers are OAuth resource servers that publish Protected Resource Metadata (RFC 9728), and clients must bind tokens to the target server with Resource Indicators (RFC 8707). See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md).
* **OBO (On-Behalf-Of):** Microsoft's name for delegated token exchange: an intermediary (an agent or server) exchanges the user's token for a new, narrowly scoped token so it can call a downstream API *as that user*. The standards-track equivalent is **RFC 8693 Token Exchange**. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **Observation Masking:** Keeping the most recent tool observations verbatim and replacing older, bulky outputs with one-line pointers to an artifact store that the agent can re-read on demand. Each edit invalidates the prompt cache from that point onward, so batch the edits. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **On-Policy Distillation (GKD):** Distillation in which the Student generates its own trajectories and the Teacher or a verifier scores or corrects them (for example, GKD; Agarwal et al., ICLR 2024). It closes the gap left by off-policy **SFT** on teacher traces, where the Student never sees its own mistakes. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Orchestrator–Workers (Dynamic Map-Reduce):** Pattern 3.1. An orchestrator LLM decides *at runtime* how many sub-tasks exist, dispatches isolated workers under a concurrency cap and timeouts, and reduces their structured outputs. Best for read-heavy fan-out; parallel writes need a shared contract and an integration check. See: [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md).
* **OSWorld (OSWorld-Verified):** Desktop computer-use benchmark (Xie et al., NeurIPS 2024) of 369 tasks in real virtual machines, each with a setup configuration and an execution-based script that checks the final machine state. **OSWorld-Verified** (2025) fixed reported task issues and improved the evaluation infrastructure, so scores on the two releases are not directly comparable. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md).
* **OTel GenAI Semantic Conventions:** OpenTelemetry's vendor-neutral span shape for AI workloads: `invoke_agent`, `chat`, and `execute_tool` spans carrying `gen_ai.*` attributes such as model, token usage, tool name, and conversation ID. Still marked experimental ("Development"), so pin versions. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Overthinking:** A reasoning model spending excessive thinking tokens on easy problems for little or no accuracy gain (documented for o1-like models by Chen et al., 2024). Mitigate it by routing easy traffic to low effort and escalating only when a cheap check fails. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **OWASP Top 10 for LLM Applications / for Agentic Applications:** The OWASP GenAI Security Project's standard threat vocabularies. The LLM list (2025) runs from LLM01 Prompt Injection to LLM10 Unbounded Consumption; the Agentic list (December 2025) runs from ASI01 Agent Goal Hijack to ASI10 Rogue Agents, and introduces the principle of **least agency**. A companion OWASP taxonomy, *Agentic AI – Threats and Mitigations* (first published February 2025), numbers agentic threats T1–T17 (for example, T1 Memory Poisoning and T2 Tool Misuse); the Agentic Top 10 cross-maps to it. Cite IDs with their edition suffix (for example, `LLM01:2025`), because OWASP renumbers entries between editions. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).

## P

* **Parallel Tool Calls:** A single model turn that emits several independent tool calls, which the runtime executes concurrently before returning one result per call ID. Disable or serialize them when calls have ordering-sensitive side effects. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 2](./chapter-02-single-agent-loops.md), [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md).
* **Parallelization (Sectioning / Voting):** Pattern 2.2. Application code fans out to concurrent agents, either different specialists on different slices of the problem (**sectioning**) or the same task several times followed by a majority vote or judge (**voting**), then fans in through a reducer or synthesizer. Branches must be truly independent and need per-branch timeouts. See: [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md).
* **pass@k:** The probability that *at least one* of $k$ attempts succeeds (popularized by Chen et al., 2021 for code generation). It flatters customer-facing agents, whose users only see one run. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **pass^k:** The probability that *all* $k$ independent trials of the same task succeed, introduced with τ-bench. It is computed per task with the unbiased estimator $\binom{c}{k}/\binom{n}{k}$ and averaged across tasks, and it measures consistency. With an 80% single-run pass rate, $0.8^5 \approx 33\%$. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **PAYGO (Pay-As-You-Go):** Shared, per-token-billed inference capacity governed by tokens-per-minute and requests-per-minute quotas; it can return HTTP 429 under bursty fan-out. Typically combined with provisioned throughput for base load. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Perceptual-Hash Frame Gating (Adaptive Frame Sampling):** Sending a new video frame to a live model only when its perceptual hash (pHash) or pixel difference from the previous frame exceeds a threshold, or when the user is actively speaking or pointing, to cap multimodal token spend. See: [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md).
* **Plan-and-Execute:** Pattern 1.2. A planner LLM writes a step checklist; a scoped executor (often a cheaper model running a small ReAct loop) performs one step in an isolated context and returns a concise summary; a **replanner** then keeps or rewrites the remaining steps. Lineage includes Plan-and-Solve and ReWOO; a lighter variant gives a single agent a to-do tool ("plan-as-a-tool"). See: [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Plan-and-Solve (PS / PS+) Prompting:** Zero-shot prompting method (Wang et al., ACL 2023) that replaces "Let's think step by step" with an instruction to first devise a plan and then carry it out, targeting missing-step errors; **PS+** adds detailed instructions (extract relevant variables, compute intermediate results carefully) aimed at calculation errors. It is a conceptual seed of **Plan-and-Execute**. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md), [Chapter 2](./chapter-02-single-agent-loops.md).
* **PoT / PAL (Program-of-Thoughts / Program-Aided Language Models):** Patterns (PoT: Chen et al., TMLR 2023; PAL: Gao et al., ICML 2023) in which the model writes its reasoning as a program that a sandboxed interpreter executes, so exact computation (arithmetic, dates, aggregation) is done by code rather than in free text. **CodeAct** applies the same idea to acting. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **PRM vs. ORM (Process vs. Outcome Reward Model):** Two kinds of trained verifier. An **ORM** scores a complete solution's final result (as in Cobbe et al., 2021); a **PRM** scores each intermediate step, so it can catch right answers reached by wrong reasoning and guide step-level search. Lightman et al. (OpenAI, ICLR 2024) found process supervision outperformed outcome supervision on MATH and released the PRM800K dataset. Both are domain-bound and open to reward hacking. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Procedural Memory:** Knowledge of *how* to act: system prompts, rules and SOPs, agent code, fine-tuned weights, and dynamically loaded skills. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Progressive Disclosure (3-Tier):** Agent Skills' loading strategy. **Tier 1** keeps only each skill's `name` and `description` in the prompt (roughly 50–100 tokens per skill); **Tier 2** loads the `SKILL.md` body when the skill triggers; **Tier 3** reads references or runs scripts only when a step needs them. Past ~50–100 skills, a semantic `skill_search` tool over names and descriptions replaces part of the in-prompt catalog. See: [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Prompt (Prefix) Caching:** Reusing computation for an exact, byte-identical prompt prefix, which bills cached input at a discount on hosted APIs and cuts time-to-first-token everywhere. One changed byte invalidates everything after it, so keep the prefix static and the history append-only. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Prompt Injection (Direct vs. Indirect):** *Direct* injection is a user typing instructions meant to override the system's rules. *Indirect* injection hides instructions in content the agent processes (emails, web pages, tickets, tool results, screenshots), exploiting the lack of a hard boundary between instructions and data in one token stream (Greshake et al., 2023). Prompt injection is OWASP LLM01. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Prompt-Injection Design Patterns:** Six architectural patterns catalogued by Beurer-Kellner et al. (2025) that stop untrusted input from triggering consequential actions: **Action-Selector**, **Plan-Then-Execute**, **LLM Map-Reduce**, **Dual LLM**, **Code-Then-Execute** (the idea behind **CaMeL**), and **Context-Minimization**. They are lighter-weight than CaMeL and trade some utility for provable limits on what injected text can do. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Provisioned Throughput:** Reserved inference capacity sized to steady-state load (for example, Azure OpenAI PTUs, Amazon Bedrock Provisioned Throughput, or Vertex AI Provisioned Throughput purchased in GSUs, or a reserved GPU pool for self-hosted models), with spillover or service tiers for peaks, and discounted **Batch APIs** (roughly 50% off, completing asynchronously) for non-urgent work. It reserves throughput; it does not hard-guarantee a TTFT. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).

## Q

* **Quadratic Context Token Tax ($O(K^2)$)** *(book term)*: The second engineering law. Re-sending a growing shared history over $K$ tool-calling turns bills $\sum_{k=1}^{K}(P + k \cdot T_{\text{obs}}) = O(K^2)$ cumulative input tokens. Sub-agent isolation and observation masking make it roughly $O(K)$; caching lowers the price but not the growth. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Query Decomposition:** Splitting a multi-part or multi-hop question into sub-queries, run in parallel when they're independent, or in sequence when each depends on the previous answer. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).

## R

* **RAG (Retrieval-Augmented Generation):** Grounding generation in a searchable, non-parametric index so answers can be fresh, cited, and permission-filtered (Lewis et al., 2020). The book's rule of thumb: *fine-tune for behavior, retrieve for knowledge*. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **RAG Poisoning (Knowledge Poisoning):** Planting or editing documents in an indexed corpus so that they are retrieved for target queries, steering answers and actions or delivering prompt injections at scale (demonstrated by PoisonedRAG; Zou et al., USENIX Security 2025). Defend with authenticated sources, reviewed ingestion, ACL partitioning, trust-weighted ranking, and citations. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **RE-Bench:** AI research-engineering benchmark (Wijk et al., METR; arXiv 2024, ICML 2025) of seven open-ended ML research-engineering environments with human-expert baselines from 8-hour attempts. Comparing agents and humans at matched time budgets shows the winner flipping as the budget changes, the clearest public demonstration that "who wins" depends on the budget. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **ReAct (Reason + Act):** Pattern 1.1 (Yao et al., 2022; ICLR 2023). The model loops Thought → Action → Observation until it decides the task is done. Modern implementations use native tool calling, reasoning models, error-as-observation, and a hard `max_steps` cap enforced in code. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Reasoning (Thinking) Model:** A model that reasons internally before answering, and with interleaved thinking between tool calls, usually under a configurable thinking budget or effort level. It makes "think step by step" prompting largely redundant and shifts effort toward clear goals, constraints, and context. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 2](./chapter-02-single-agent-loops.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Reasoning Escalation Ladder** *(book term)*: Appendix B's six rungs for adding reasoning compute, each justified by eval evidence on a failing task category: R0 direct answer → R1 prompted or native reasoning → R2 tuned per-node effort and difficulty-aware routing → R3 verified breadth (Best-of-$N$, Self-Consistency) → R4 grounded loops (ReAct, ReWOO, LLMCompiler, CRITIC, Reflexion) → R5 search over trajectories (LATS or MCTS in sandboxes). Don't skip rungs. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Recall@K:** The fraction of queries whose gold evidence appears in the top $K$ retrieved results; the first metric to check when a RAG answer is wrong. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md), [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Reducer (State Reducer):** A merge function for shared state that combines concurrent writes (for example, `Annotated[list, operator.add]` in LangGraph) or records them as conflicts, instead of letting the last writer silently win. See: [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md), [Chapter 5](./chapter-05-decentralized-and-emergent-topologies.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Reflexion:** Method (Shinn et al., NeurIPS 2023) in which an agent turns failed trials, judged by an evaluator, into verbal lessons stored in episodic memory for the next trial, with no weight updates. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **ReWOO:** Planning method (Xu et al., 2023) that emits all tool calls up front, with placeholders (`#E1`, `#E2`) for results that are filled in later, decoupling reasoning from observations. LLMCompiler extends the idea by scheduling independent steps in parallel. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **RFT (Reinforcement Fine-Tuning):** RL fine-tuning against deterministic graders (tests, SQL sandboxes, schema checks) plus a step-efficiency penalty. Guard against reward hacking by auditing high-reward trajectories and keeping a held-out eval. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Roots / Sampling (MCP, deprecated):** Client-side features from earlier MCP specs. **Roots** told a server which directories or workspace URIs to operate within (a hint, not a sandbox); **Sampling** let a server request an LLM completion through the host. Both, along with protocol-level Logging, are deprecated in `2026-07-28`. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **Router Skill:** A single top-level skill whose `SKILL.md` maps sub-domains to child playbooks, creating a two-level index of procedural memory that keeps the root catalog small. See: [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md).
* **RRF (Reciprocal Rank Fusion):** Fusion method (Cormack et al., 2009) that merges ranked lists by summing $1/(k + \text{rank})$ for each document (typically $k \approx 60$). Because it uses only ranks, it avoids calibrating BM25 scores against cosine similarities. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Rule of Two (Agents):** Meta's guideline (October 2025): within one session an agent should have at most two of (A) processing untrustworthy inputs, (B) access to sensitive systems or private data, and (C) the ability to change state or communicate externally. A workflow that needs all three requires human approval. Unlike the lethal trifecta, it also covers state-changing harm. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).

## S

* **Self-Consistency:** Sampling several reasoning paths and taking the majority answer (Wang et al., ICLR 2023); the basis of voting ensembles. For free-form outputs where exact-match voting is impossible, *Universal Self-Consistency* (Chen et al., 2023) gives all candidates to an LLM and asks it to pick the most consistent one. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Self-Preference Bias:** An LLM judge's tendency to recognize and favor its own generations (Panickssery, Bowman & Feng, NeurIPS 2024). Reduced, not removed, by using a critic or judge from a different model family. See: [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **Self-RAG:** Method (Asai et al., ICLR 2024) that fine-tunes a generator to emit inline reflection tokens (`[Retrieve]`, `[IsRel]`, `[IsSup]`, `[IsUse]`) so it can retrieve on demand and critique its own output. Production systems usually emulate these gates with LLM-judge calls. See: [Chapter 7](./chapter-07-agentic-rag-and-knowledge-grounding.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Self-Refine:** Intrinsic self-refinement (Madaan et al., NeurIPS 2023): draft, critique against a rubric, and rewrite within a single episode, using working memory only. Useful for formatting and tone; risky for reasoning without external grounding. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Semantic Caching:** Returning a cached answer or retrieval result when a new query's embedding is close enough to a previous one, with the cache key scoped by tenant, permissions, and corpus version. Risks false hits ("cancel my order" vs. "cancel my subscription") and staleness, so use strict thresholds and TTLs. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Appendix A](./appendix-a-rag-patterns-deep-dive.md).
* **Semantic Memory:** Facts about the user, the domain, or the world, retrieved via RAG, SQL, key-value stores, or knowledge graphs. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Sequential Chaining / Pipeline (Prompt Chaining):** Pattern 2.1. Application code runs a fixed, linear sequence of narrow specialist agents, each with only its stage's tools and a strict output schema, separated by deterministic **code gates**. Latency is the sum of the stages, and the pipeline cannot backtrack without a cyclic graph. Anthropic's name for this workflow is *prompt chaining*. See: [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md).
* **Set-of-Mark (SoM) Prompting:** Visual grounding technique (Yang et al., Microsoft, 2023) that draws numbered badges on interactive elements in a screenshot, so a vision-language model selects an element ID (`click(mark_id=14)`) instead of guessing raw pixel coordinates. See: [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **SFT (Supervised Fine-Tuning):** Training on input-to-target pairs. For agent distillation, the pairs are verified teacher trajectories (context → visible rationale + tool call). SFT is off-policy, so on-policy distillation (for example, GKD) can close the remaining gap. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Shadow & Canary Deployment:** A staged rollout. **Shadow mode** mirrors a sample of live traffic to the candidate (for example, a distilled Student), discards its output, and stubs its side effects; a **canary** then sends a small share of real traffic to it with automated rollback on regressions; finally a verifier-gated cascade escalates hard cases to the stronger model. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Signing & Provenance:** Cryptographically recording who published an instruction-bearing artifact and detecting any change to it: Sigstore-based signatures for software and models (for example, the OpenSSF model-signing work), build provenance, JWS-signed Agent Cards, fingerprinted tool definitions, and provenance tags on memory and indexed documents. Signing proves origin and integrity, not safety, so it complements review rather than replacing it. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md), [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md).
* **`SKILL.md`:** The required file of an Agent Skill: YAML frontmatter (`name` and `description` required; optional `license`, `compatibility`, `metadata`, and experimental `allowed-tools`) plus a Markdown playbook. The `description` is the trigger specification, and the spec recommends keeping the file under roughly 500 lines / 5,000 tokens. See: [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md).
* **Spectrum of Agency** *(book term)*: Five stages: pure LLM call → augmented LLM → deterministic workflow → autonomous single agent → LLM-coordinated multi-agent system. Control-flow ownership and agent count are separate axes: adding agents is not adding agency. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md).
* **Spotlighting:** A family of prompt transformations (Hines et al., Microsoft, 2024) that continuously mark untrusted input so the model can tell data from instructions: **delimiting**, **datamarking** (a marker token interleaved through the text), and **encoding** (for example, Base64). It lowers indirect-injection success but gives no guarantee. See: [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **STATE_DELTA:** AG-UI event that carries RFC 6902 JSON Patch operations against the shared state, with periodic `STATE_SNAPSHOT` events for resynchronization. It powers co-pilot "shared canvas" interfaces where human and agent edit the same object. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **Step-Level Fault Attribution (Waterfall):** Walking a failed trace's intermediate checkpoints in order and blaming the *earliest* failing step (routing → retrieval/context → tool execution/schema → reasoning/synthesis), because later failures are often downstream consequences. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Streamable HTTP (vs. `stdio`):** MCP's two standard transports. `stdio` runs the server as a local child process speaking newline-delimited JSON-RPC over stdin/stdout. **Streamable HTTP** exposes a single HTTP endpoint where each client message is a POST answered with JSON or a request-scoped SSE stream; it replaced the deprecated HTTP+SSE transport and, as of `2026-07-28`, is stateless (no `Mcp-Session-Id`). See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **Sub-Agent Context Isolation:** Delegating noisy, multi-step work to a sub-agent with its own context window that returns only a condensed, structured answer. It keeps the parent's context small and clean. Compared with one long loop that re-sends every bulky observation, it can cut cumulative input tokens (Chapter 1's worked example: about 5× fewer). Compared with a single chat, though, a multi-agent system spends far more tokens in total (Anthropic reported about 15× for its multi-agent research system), so reserve it for noisy or parallelizable work. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md), [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Swarm (Decentralized Handoffs):** Pattern 4.1. Exactly one specialist holds the "active pointer" at a time and hands control directly to peers without a central hub, so each user turn costs one agent loop with no supervisor hop. In multi-turn conversations this can roughly halve per-turn latency and cost compared with a supervisor. Requires a cycle breaker (tracking `visited_edges` and capping handoffs per turn) and a handoff-context policy. See: [Chapter 5](./chapter-05-decentralized-and-emergent-topologies.md).
* **SWE-bench (Family):** Repository-level issue-resolution benchmarks (Jimenez et al., ICLR 2024): given a repository snapshot and a GitHub issue, the agent writes a patch, which counts as **resolved** only if the hidden fail-to-pass tests now pass and the pass-to-pass tests still pass. Variants include Lite, **Verified** (a human-screened 500-task subset released by OpenAI with the SWE-bench authors, 2024), Multimodal, and others. Watch for weak tests, solution leakage, and scaffold overfitting. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md).
* **Sycophantic Flip-Flop:** A model abandoning an answer, often a correct one, when merely challenged ("Are you sure?"). It is why ungrounded self-reflection can lower accuracy, and why deterministic verifiers should run before any LLM critique. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).

## T

* **Taint Tracking:** Attaching provenance (for example, "untrusted external") to values and propagating it to everything derived from them, so policies can stop tainted data from choosing recipients, URLs, or actions. Tainted data may still be carried as content. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Task (A2A):** A2A's stateful unit of work, grouped into conversations by `contextId`. It moves from `TASK_STATE_SUBMITTED` and `TASK_STATE_WORKING`, through interrupted states (`TASK_STATE_INPUT_REQUIRED`, `TASK_STATE_AUTH_REQUIRED`), to a terminal state (`TASK_STATE_COMPLETED`, `TASK_STATE_FAILED`, `TASK_STATE_CANCELED`, or `TASK_STATE_REJECTED`). Deliverables arrive as `Artifact`s made of `Part`s. For simple interactions, `SendMessage` can return a direct `Message` instead of a Task. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **TBOM (Token Bill of Materials)** *(book term)*: The decomposition of an invocation's tokens into six components: static system prefix, tool and skill schemas, retrieved RAG/memory, cumulative turn history, reasoning/thinking tokens, and retry/critic loops. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **TCT (Task Completion Time):** End-to-end wall-clock time across all serial LLM calls and tool executions, $\sum_{k}(\text{TTFT}_k + N_{\text{out},k} \cdot \text{TPOT}_k + L_{\text{tool},k})$, where output tokens include thinking tokens; parallel groups contribute their slowest branch. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Telephone Game:** Information loss as free-text summaries are re-summarized up a hierarchy, dropping constraints, numbers, and citations. Fixed by having agents write validated, structured facts with provenance to typed shared state. See: [Chapter 4](./chapter-04-dynamic-and-hierarchical-orchestration.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Terminal-Bench:** Command-line agent benchmark (Merrill et al., ICLR 2026). Version 2.0 is a curated set of 89 hard tasks spanning software engineering, system administration, data processing, and security, each with its own container environment, a human-written reference solution, and verification tests. With so few tasks, cite the dataset version and report confidence intervals. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **Test-Time (Inference-Time) Compute:** Extra computation spent per request to improve the answer, along four axes: *depth* (longer reasoning), *breadth* (more samples), *search* (branch, evaluate, backtrack), and *grounding* (external feedback). Only grounding adds new information; the others pay off only when a selection signal can tell good candidates from bad. Snell et al. (ICLR 2025) showed that allocating it per prompt by difficulty beats a uniform Best-of-$N$ budget. See: [Appendix B](./appendix-b-reasoning-and-planning-patterns.md), [Chapter 2](./chapter-02-single-agent-loops.md).
* **TextGrad:** Optimization framework (Yuksekgonul et al.; preprint 2024, published in *Nature* 2025) that "backpropagates" LLM-written textual feedback through a compound AI system to improve its prompts and components. See: [Chapter 16](./chapter-16-agent-quality-flywheel-and-distillation.md).
* **Thinking Budget (Effort Level):** A per-request cap on a reasoning model's internal thinking (parameter names differ by provider). Thinking tokens are billed at the output-token rate and add directly to latency, so use the lowest setting that passes your evals. A budget is a cap, not a target. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Three Pillars of Agent Evaluation** *(book term)*: *Trajectory* (did it take the right path and call the right tools?), *outcome* (is the answer faithful, complete, and safe?), and *efficiency/cost* (latency, steps, TBOM, CpO), reported side by side. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **Time-Travel (Replay & Fork):** Loading an earlier checkpoint, editing state or prompt, and forking a new execution branch without re-running earlier steps. It rewinds *your* state, not side effects already committed in the outside world. See: [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md).
* **Token Exchange (RFC 8693):** The OAuth 2.0 grant that swaps one token for another. For agents, the new short-lived token names the human user as `sub`, the acting agent in `act`, a narrowed `scope`, and a single-resource `aud`; downstream services verify it and enforce row-level security from its claims. MCP servers must never use **token passthrough** (forwarding the client's token downstream); when they need to call an upstream API as the user, they obtain a separate, narrowly scoped token, typically through token exchange. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Token Passthrough:** An anti-pattern in which an MCP server accepts a client's token without checking that it was issued for *that* server and forwards it unchanged to downstream APIs, breaking audience boundaries and creating a **confused deputy**. The MCP specification forbids it; require audience-bound tokens (RFC 8707) and use **token exchange** (RFC 8693) for downstream calls. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **TokenBudgetEnforcer** *(book term)*: The book's request-scoped circuit breaker, shared by the root agent and all sub-agents. It preflights each LLM call against worst-case cost, records actual usage afterwards, and trips when a dollar or token cap is exceeded. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **Tool Annotations (MCP):** Behavior hints a server attaches to a tool (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) to drive approval UX and retry policy. They are untrusted hints, not guarantees. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md).
* **Tool Calling (Function Calling):** A two-party handshake: the model emits a structured call (name, arguments, call ID) against declared JSON Schemas, and the application runtime validates and executes it and returns the result linked to that call ID. The model never executes tools itself. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md).
* **`tool_choice`:** API setting that controls whether the model may call tools, must call some tool, must call a specific tool, or must not call tools. See: [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **Tool Poisoning (and Tool Shadowing):** Hiding malicious instructions inside a tool's description or schema, visible to the model but not the user. In *tool shadowing*, one server's description manipulates how the agent uses another server's tools, or registers a colliding name. In a *rug pull*, a server silently changes a tool's definition after it was approved. Mitigated by allowlisting servers, pinning definitions by digest and re-approving on change, and namespacing tools per server. See: [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **ToolBench / StableToolBench:** Large-catalog tool-use benchmark from the ToolLLM paper (Qin et al., ICLR 2024), built on more than 16,000 real RESTful APIs and graded by an LLM judge (ToolEval). Because live APIs change or disappear, **StableToolBench** (Guo et al., Findings of ACL 2024) adds a virtual API server of cached and simulated responses. Pin and report the judge model. See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).
* **TPOT / ITL (Time Per Output Token / Inter-Token Latency):** Decode-speed metrics, dominated by memory-bandwidth-bound autoregressive generation; they scale with the model's active parameter count, KV-cache size, and server load. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md).
* **Trajectory Match Modes:** Ways to compare an agent's actual tool-call sequence with a reference: *exact* match, *in-order* (subsequence; extra calls allowed, the recommended default for sequential tasks), *any-order* (superset), and continuous *tool precision/recall*. Match critical arguments, not just tool names. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md).
* **Tree-of-Thoughts (ToT):** Search over partial "thoughts" (Yao et al., NeurIPS 2023): expand several candidates per step, score them with a heuristic or verifier, and prune or backtrack (BFS/DFS). Reasoning models have internalized much of this search. See: [Chapter 2](./chapter-02-single-agent-loops.md), [Appendix B](./appendix-b-reasoning-and-planning-patterns.md).
* **Tripwire Guardrail:** A lightweight classifier or rule check on inputs, tool calls, or outputs that aborts the run when it fires. It can run in parallel with the model to save latency, but must *block* mutating tool calls until it passes. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 17](./chapter-17-production-state-hitl-and-frameworks.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **TTFT (Time to First Token):** Queueing plus prefill time before the first output token. It grows with *uncached* input length and drops sharply on long-prefix cache hits. See: [Chapter 13](./chapter-13-agentic-finops-and-tokenomics.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).
* **τ-bench (tau-bench):** Benchmark of tool-using customer-service agents operating under domain policies with simulated users (Yao, Shinn, Razavi & Narasimhan; arXiv 2024, ICLR 2025). It grades by comparing the final database state with the expected state and introduced `pass^k`; τ²-bench adds a dual-control setting in which the user also acts. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).

## U

* **UCP (Universal Commerce Protocol):** Commerce protocol launched by Google with retail partners (January 2026) that covers the shopping journey from discovery through checkout to post-purchase, using machine-readable merchant capability profiles; designed to work with AP2 for payment authorization. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).
* **Untrusted Input:** The book's standing rule that everything crossing a protocol plane (tool descriptions and results, retrieved documents, remote agents' messages and Agent Cards, on-screen pixels) is *data* that may carry injected instructions, and never grants authority by itself. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 9](./chapter-09-mcp-and-a2a-interoperability.md), [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **User Simulator (Persona-Driven):** An LLM given a hidden scenario goal and persona that converses with the agent under test for several turns, so multi-turn evals tolerate variation in the agent's phrasing. Pin its model and temperature and give it explicit stop conditions. See: [Chapter 10](./chapter-10-agentic-evaluation-and-observability.md), [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md).

## V

* **VAD (Voice Activity Detection):** Detecting user speech in an audio stream. Server-side VAD, either silence-based or semantic (end-of-thought), triggers barge-in cancellation in live voice agents. See: [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md).
* **Verifiable Digital Credential (VDC):** A tamper-evident, cryptographically signed object. AP2 implements its Intent, Cart, and Payment Mandates as VDCs to create a non-repudiable audit trail of what the user authorized. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).

## W

* **Wasm (WebAssembly / WASI) Sandbox:** A memory-safe, capability-based bytecode sandbox with no file, network, or syscall access unless explicitly granted, and near-instant startup. Suited to lightweight parsing and math plugins; its ecosystem is limited for general Python workloads. See: [Chapter 12](./chapter-12-agentic-security-identity-and-sandboxing.md), [Chapter 6](./chapter-06-tool-calling-and-action-engineering.md), [Appendix D](./appendix-d-agentic-threat-and-defense-catalog.md).
* **WebArena / VisualWebArena:** Web-agent benchmarks on self-hosted websites that are reset between runs. WebArena (Zhou et al., ICLR 2024) has 812 long-horizon tasks across e-commerce, a forum, collaborative software development, and content management, checked by programmatic evaluators of the answer or site state. VisualWebArena (Koh et al., ACL 2024) adds 910 tasks that need visual understanding. Report the observation format (accessibility tree, screenshot, or set-of-marks). See: [Appendix C](./appendix-c-agent-benchmarks-and-evaluation-datasets.md), [Chapter 14](./chapter-14-multimodal-computer-use-and-streaming-agents.md).
* **Workflow:** A system in which LLMs and tools are orchestrated through predefined code paths, so application code owns the control flow. Five LLM "agents" wired into a fixed pipeline are still a workflow. Contrast **Agent**. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 3](./chapter-03-deterministic-multi-agent-workflows.md).
* **Working Memory:** Everything currently inside the context window or session state (messages, task variables, recent observations); the only memory the model actually "sees". The other memory types matter only once something retrieves them into it. See: [Chapter 1](./chapter-01-foundations-and-mental-models.md), [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).

## X

* **x402:** Open payment protocol that revives the HTTP `402 Payment Required` status code for programmatic stablecoin payments. Created by Coinbase, it is now stewarded by the vendor-neutral x402 Foundation under the Linux Foundation. AP2 has an x402 extension. See: [Chapter 15](./chapter-15-agent-to-frontend-ux-and-commerce-protocols.md).

## Y

* **YAML Frontmatter (Skill):** The metadata block at the top of `SKILL.md`. `name` (at most 64 characters of lowercase letters, digits, and hyphens, matching the folder name) and `description` (at most 1,024 characters) are required, and they are the only fields loaded into the Tier-1 catalog. See: [Chapter 8](./chapter-08-agent-skills-and-procedural-memory.md).

## Z

* **Zep / Graphiti:** A long-term memory layer (Zep; Rasmussen et al., 2025) built on Graphiti, a temporal knowledge-graph engine. It tracks bi-temporal validity on every edge and invalidates superseded facts instead of deleting them. See: [Chapter 11](./chapter-11-context-engineering-and-long-term-memory.md).

## Summary

Control flow is the first question to ask about any system. *Workflow* vs. *agent* is about who owns control flow, not how many LLMs are involved, and the Golden Rule says to hand control to an LLM only where the path can't be known in advance.

The protocols map to planes. MCP (tools and data), A2A (peer agents), AG-UI + A2UI (frontends), and AP2 (payments) are complementary layers, and anything crossing any of them is untrusted input.

Measure what users experience: `pass^k` over `pass@k`, CpO over price per token, and the Three Pillars over final-answer-only grading. And treat context as a budget. The Quadratic Context Token Tax, context rot, and prompt caching explain most of the context-engineering and FinOps techniques in this book.
